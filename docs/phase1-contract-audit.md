## Evidence interpretation

The `contracts.json` vectors are hand-maintained, versioned boundary fixtures (`phase1-contracts-v1`); they pin v1 contract identities and field/action meanings but do not replace the engine or observation compatibility versions. Go and Python both load the same fixture and validate family presence and unique case names. `golden.json` remains the Python v0 reference output. The fixture corpus and harness make Phase 1 checks reproducible. The fresh report records all five checks passed at `0287a0f` with a dirty worktree; its hashes bind the run to the exact golden and contract fixtures used.

`15bdb5c` added the shared contract corpus, Go/Python consumers, and canonical/fine-time behavior. `3bcb69f` added the combined harness and non-mutating golden drift check. `0287a0f` pinned reference generation to an explicit 512-significant-digit half-even context and recorded legacy float-timer tie differences. Root reviewed this mapping and the direct five-step execution output before closing the section 12 Phase 1 checkpoint. The retained JSON is the run's original bytes, not a reconstructed result.

## Phase boundary

Phase 1 exit criteria in §12 are: generated Go/Python messages, an executable schema-conformance harness, a clear current policy/observation version mapping, and a green Python suite. The fresh report provides direct local evidence for the executable checks at its recorded revision and worktree state. Passing Phase 1 does not establish Phase 2's broader generated event-sequence/fuzz coverage, all economic parity, or performance. It also does not establish Phase 4's Go bridge performance/default-backend switch, remote CI execution, live exchange behavior, or product capacity; those remain separately scoped gates in the plan.
