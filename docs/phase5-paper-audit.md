# Phase 5 durable paper execution audit

This draft maps the Phase 5 implementation and exit criteria in [the Go runtime plan, §12](go-runtime-plan.md#12-migration-phases-and-gates) to the PostgreSQL paper runtime, tests, and retained process evidence. It preserves the plan's full scope and does not mark the phase complete. In particular, a PostgreSQL fence for simulated paper effects is not a fence for a private exchange sender, and process recovery is not a database backup/restore drill.

## Recovery evidence boundaries

There are two distinct local proofs in the current evidence. Three repeated ordinary-process recovery trials killed and resumed one synthetic paper account while a bystander remained active and HTTP reads continued; each trial completed the financial and process audits, but each had zero observed-minus-processed source debt at the crash boundary. As documented in [`benchmarks/results/paper-recovery-load-20261029/README.md`](../benchmarks/results/paper-recovery-load-20261029/README.md), this is recovery under modest read demand, not a backlog-drain or headroom measurement.

Separately, [`TestFactQuantumBoundsCountAndElapsedInsideTransport`](../internal/runtime/fact_quantum_test.go) stores 512 distinct partial fills as one accepted paper outcome and reconstructs them under a fresh owner. It checks all 512 fills, exact final balances (1.0256 BTC and 997.4630656 USD), cleared reservations, a paused parent, readiness, and matching observed/processed cursors. [`TestFactQuantumControlAckPrecedesPrefixCompletionAndMarketsStayOrdered`](../internal/runtime/fact_quantum_test.go) also checks controls and reads during a bounded reduction prefix. These are real PostgreSQL-backed fresh-owner tests, but they are not an ordinary daemon SIGKILL trial with accepted backlog.

[`TestPaperProcessAcceptedBacklogRecoveryWithBystanderDemand`](../cmd/liquiditylabd/paper_load_recovery_backlog_test.go) adds an ordinary-daemon SIGKILL/reap/resume trial with an explicit accepted partial batch. Before the read schedule, it confirms a Linux SIGSTOP, no open victim database transaction, an ownership lease with more than ten seconds remaining, and a caught-up open passive child, then records 128 harness-authored partial fills through the owned transport-observation path. The read schedules start immediately before SIGCONT, which releases the victim into the measured schedule. A pass requires a strict nonempty, not-fully-applied batch prefix after reap, with accepted debt and the child reservation retained, followed by complete recovery and financial audit. The post-reap prefix may be longer than the first prefix observed before SIGKILL; it must still remain a strict prefix. This fixture is not emitted by the ordinary 2 Hz source and does not measure natural feed backlog or capacity. The full daemon race suite, including this test, passed in 64.615 seconds against real PostgreSQL per the run owner. A clean retained repeat and full product validation remain pending. The 512-fill fresh-owner test is separate evidence.

## Missing and separate gates

- **Ordinary-process recovery with accepted backlog:** the explicit 128-fill process-recovery test is implemented and included in a passing 64.615-second full daemon race suite against real PostgreSQL. A clean retained repeat and full product validation remain pending. The three retained ordinary 2 Hz process trials still had zero source debt and do not prove recovery of a naturally accumulated source backlog; the controlled harness-authored batch is not a source-rate or capacity result.
- **Private exchange sender isolation and failover:** not supplied by `postgres-paper-v1`. A database epoch can reject stale PostgreSQL writes, but cannot fence a live remote connection. The plan's reconciliation, exchange-confirmed fill/cancel, and private snapshot/stream handoff remain separate implementation and pilot gates.
- **Backup/restore:** no backup/WAL restore drill into an isolated paused deployment is evidenced here. Process restart against the same live database is not a database restore.
- **Capacity, overload/headroom, sustained soak, and production operations:** not established by the three short process trials or the 512-fill deterministic owner test. Broader release gates remain in the plan.

These gaps preserve the plan's full scope. This audit is an evidence map, not Phase 5 sign-off or authorization for live execution.
