# Durable runtime evidence — 2026-10-28

This directory preserves the 11 complete reports from the recorded stage 2 run. Each `.json.gz` file is deterministic gzip (`mtime=0`) of the exact source report; `manifest.json` records both byte lengths and SHA-256 values, embedded binary identity, run validity, workload counts, source-manifest hash checks, financial audit, final recovery debt, gauges, and local account references. `summary.json` contains per-run latency/resource/WAL observations, counter and histogram interval differences where endpoints permit them, and observed per-rate integrity results. Histogram differences include only counts, sums, and bucket counts; do not difference min/max or quantiles.

## Reproduction

Follow the [runtime benchmark instructions](../../runtime/README.md). These archived reports use schema v1 and were built from source revision `4b58b319da72e3f54b162683dc076f6df7fbc43e` (`go1.26.8`, build VCS metadata enabled). To reproduce this exact report schema, use that revision in a fresh disposable checkout and build/run it as described there; the current runner may emit schema v2 and is not an exact reproduction of these archived reports. The baseline consists of three metrics-off and three metrics-on trials at 10 market events/s and 2 views/s, each with a 2-second warmup and 20-second measurement. The five single-trial ramps used a 1-second warmup and 5-second measurement: 50, 100, 250, and 500 market events/s at 2 views/s, plus 500 market events/s at 500 views/s. The 500-rate reports are retained in full despite invalid source delivery and runner rejections.

The observed baseline on/off medians are descriptive only. Final decision counts differed between runs with wall-clock scheduling, so these runs do not establish causal instrumentation overhead. The ramp observations are not an SLO or capacity claim. At 500 market events/s, reports show ordered-source-queue rejections; pool maximum was four, shutdown showed one connection, and canceled acquire count was zero. This identifies the first observed backlog location, while its resource cause still needs profiling.

All runs report valid financial conservation and zero final source-recovery debt, including the invalid source-delivery trials. Invalid status reflects workload/source-delivery validity, not a discarded run. Account references in the manifest are local benchmark identifiers, not credentials.
